# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A path tracer (CPU and Vulkan-compute GPU paths, toggled at runtime, optionally using hardware ray tracing) built on [Walnut](https://github.com/TheCherno/Walnut) (Dear ImGui + GLFW + Vulkan app framework), started from The Cherno's Ray Tracing series. Windows / Visual Studio 2022 only.

## Setup & build

The build is generated by Premake; there is no committed `.sln`/`.vcxproj` (they are gitignored).

1. `git clone --recursive` — the `Walnut/` submodule must be populated. If the repo was cloned non-recursively, run `git submodule update --init --recursive`. Walnut ships the `premake5.exe` used below at `Walnut/vendor/bin/`.
2. Install the [Vulkan SDK](https://vulkan.lunarg.com/); the `VULKAN_SDK` env var must be set (consumed as `IncludeDir.VulkanSDK` in `Walnut/WalnutExternal.lua`).
3. Run `scripts/Setup.bat` (it `pushd`es to repo root and runs `premake5.exe vs2022`), or from repo root directly: `Walnut\vendor\bin\premake5.exe vs2022`.
4. Open the generated `RayTracing.sln`, build/run with F5.

Re-run step 3 whenever source files are added/removed or the `premake5.lua` files change. Prebuild steps (in `RayTracing/premake5.lua`) compile the compute shaders with the Vulkan SDK's `glslc.exe` on every build: `PathTrace.comp` → `PathTrace.comp.spv` and (with `-DUSE_RAY_QUERY --target-env=vulkan1.2`) → `PathTraceRQ.comp.spv`, and `Denoise.comp` → `Denoise.comp.spv`. The `.spv` files are gitignored. `debugdir` is the `RayTracing/` project folder so the relative shader paths resolve the same under F5 and when running the exe directly.

**Walnut override.** The root `premake5.lua` removes Walnut's `Application.cpp` from the Walnut project and compiles `WalnutOverride/Application.cpp` (a copy, changes marked `RayTracing:`) instead: it targets Vulkan 1.2 and enables `VK_KHR_acceleration_structure` / `VK_KHR_ray_query` / buffer device addresses when supported (`WalnutExtensions::IsRayQuerySupported()`). Never edit the `Walnut/` submodule itself.

### Configurations

- **Debug** — unoptimized, very slow for a path tracer; enables the Vulkan validation layer (useful for checking GPU code).
- **Release** — optimized, keeps console + symbols. Use this for development.
- **Dist** — optimized `WindowedApp` (no console), `WL_DIST` defined.

There is no test suite and no linter. For checks, use the command line (see `AppOptions` in `WalnutApp.cpp`): `RayTracing.exe --scene scenes/X.json --render out.png|out.hdr --samples N [--cpu|--gpu] [--no-hwrt] [--no-light-sampling] [--denoise] [--compare split|difference]` renders, saves and exits; `--save-scene` round-trips scene files. Comparing the CPU and GPU renders of the same scene is the main correctness check (they use the same RNG and should agree closely); use linear `.hdr` output when comparing means.

## Architecture

**CPU/GPU parity is the core invariant.** Every shading/sampling routine exists twice, kept line-for-line in sync: `BSDF.h` ↔ `shaders/BSDF.glsl`, `Intersection.h` ↔ `Intersection.glsl`, `LightSampling.h` ↔ `LightSampling.glsl`, `EnvironmentSampling.h` ↔ `Environment.glsl`, `ToneMapping.h` ↔ `ToneMapping.glsl`, `Denoiser.cpp` ↔ `Denoise.comp`, and `Renderer::PerPixel/TraceRay/ClosestHit` ↔ the same functions in `PathTrace.comp`. Random numbers must be drawn in the same order on both sides (draw them into variables one at a time; don't rely on argument evaluation order).

**Entry point / UI (`WalnutApp.cpp`).** `AppLayer` owns the `Renderer`, `Camera` and `Scene`, draws the Settings / Scene / Materials / Environment / Viewport panels, handles File menu + shortcuts (scene new/open/save, image export), viewport picking (left click selects, Ctrl+click focuses), and the command-line batch mode. Any scene edit sets `m_SceneChanged`, which restarts accumulation. The menu-bar callback holds only a `weak_ptr` to the layer (the layer must die when Walnut clears its layer stack, while the device is alive).

**Scene (`Scene.h`, `Mesh.h`, `EnvironmentMap.h`).** Materials (albedo, roughness, metallic, transmission, IOR, emission), spheres, infinite planes, meshes (`Mesh`: object-space triangles + BVH, shared) placed by `MeshInstance`s (TRS transform + material), and `SkySettings` (none / gradient / HDR environment map). `ObjectRef` identifies an object. `Scene::GeometryVersion` changes whenever mesh geometry changes so the GPU knows to re-upload. Meshes come from `MeshLoader::Load` (`builtin:box|quad|sphere` or `.obj`), which also builds the BVH (`BVH.cpp`, binned SAH, reorders triangles). `SceneSerializer` reads/writes JSON (`Json.h` is a small in-repo parser); sample scenes live in `RayTracing/scenes/`. Emission is one-sided (front face only).

**Renderer (`Renderer.cpp`).** Each frame: `PreparedScene::Prepare` (instance matrices, light list with power-based CDF, environment sampling probability — shared by both paths), then builds `FrameParams` (reset / first sample index / sample count, honouring Samples per Frame and Max Samples) and runs the GPU path, the CPU path, or both (compare modes). The accumulation buffers hold radiance sums with the sample count in alpha, plus denoiser features (albedo+depth, normal+luminance²). Converged images are still re-resolved every frame so exposure/tone mapping/denoiser settings stay live.

CPU path: `PerPixel` generates a thin-lens camera ray with sub-pixel jitter, then per bounce: `TraceRay` (spheres, planes, per-instance BVH traversal in object space) → MIS-weighted emission → next-event estimation (`SampleDirectLight`: a light or the environment, shadow ray, power heuristic) → `BSDF::SampleDirection` (GGX specular + Lambert diffuse + rough dielectric "glass" lobe) → Russian roulette. Light sampling is skipped at the last bounce and for pure glass.

**GPU path (`GpuPathTracer.cpp`, `shaders/PathTrace.comp`).** A hand-rolled Vulkan compute pipeline against Walnut's raw handles (`GetDevice`/`GetCommandBuffer`/`FlushCommandBuffer` — synchronous — and `SubmitResourceFree`). It never uses `Walnut::Image`: it owns its storage images (display rgba8 registered with ImGui via `ImGui_ImplVulkan_AddTexture`, accumulation and feature images rgba32f, all permanently in `VK_IMAGE_LAYOUT_GENERAL`). Descriptor bindings are listed in one table (`Binding` enum / `BindingTypes`) that must match the shader's `layout(binding = N)`. Small per-frame data goes through grow-on-demand host-visible buffers (`Upload`); big static data (mesh vertices/indices/BVH nodes, environment map) through device-local buffers filled by staging copies (`UploadStatic`). With hardware RT, `RayQueryScene` keeps a BLAS per mesh plus an instanced unit-sphere AABB BLAS and rebuilds the TLAS every frame; the `PathTraceRQ` pipeline variant traces spheres/meshes with `rayQueryEXT` (planes stay in a shader loop). The denoiser runs as a second pipeline (`Denoise.comp`, one dispatch per à-trous pass) that writes the display image. Generic Vulkan helpers live in `VulkanHelpers.h`.

**RNG.** `Utils::PCG_Hash` / `RandomFloat` (uniform in [0,1) from 24 bits — it must never return 1) seeded per (pixel, sample index); `Settings.SlowRandom` swaps in `Walnut::Random` on the CPU only.

**Camera (`Camera.cpp`).** Ray directions are computed per sample from the inverse projection/view (no per-pixel cache) via `GetRayDirection` / `GenerateRay` (thin lens: aperture + focus distance). Controls: hold **right mouse** to look; **WASD** move, **Q/E** down/up.
