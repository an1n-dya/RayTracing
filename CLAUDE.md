# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A path tracer (CPU and Vulkan-compute GPU paths, toggled at runtime) built on [Walnut](https://github.com/TheCherno/Walnut) (Dear ImGui + GLFW + Vulkan app framework), following The Cherno's Ray Tracing series. Windows / Visual Studio 2022 only.

## Setup & build

The build is generated by Premake; there is no committed `.sln`/`.vcxproj` (they are gitignored).

1. `git clone --recursive` — the `Walnut/` submodule must be populated. If the repo was cloned non-recursively, run `git submodule update --init --recursive`. Walnut ships the `premake5.exe` used below at `Walnut/vendor/bin/`.
2. Install the [Vulkan SDK](https://vulkan.lunarg.com/); the `VULKAN_SDK` env var must be set (consumed as `IncludeDir.VulkanSDK` in `Walnut/WalnutExternal.lua`).
3. Run `scripts/Setup.bat` (it `pushd`es to repo root and runs `premake5.exe vs2022`), or from repo root directly: `Walnut\vendor\bin\premake5.exe vs2022`.
4. Open the generated `RayTracing.sln`, build/run with F5.

Re-run step 3 whenever source files are added/removed or the `premake5.lua` files change. A prebuild step (in `RayTracing/premake5.lua`) compiles `RayTracing/src/shaders/PathTrace.comp` to `PathTrace.comp.spv` via the Vulkan SDK's `glslc.exe` on every build; the `.spv` is gitignored. `debugdir` is set to the `RayTracing/` project folder so that relative path resolves the same way under F5 and when running the built exe directly.

### Configurations

- **Debug** — unoptimized, very slow for a path tracer; avoid for actual rendering.
- **Release** — optimized, keeps console + symbols. Use this for development.
- **Dist** — optimized `WindowedApp` (no console), `WL_DIST` defined.

There is no test suite and no linter.

## Architecture

**Entry point.** `Walnut::CreateApplication` in `RayTracing/src/WalnutApp.cpp` builds the `Walnut::Application`, pushes a single `AppLayer`, and wires the menu bar. Walnut owns the window/Vulkan/ImGui loop and calls back into the layer.

**Frame loop.** `AppLayer::OnUIRender` runs every frame: it draws the Settings / Scene / Viewport ImGui windows and then calls `Render()` unconditionally at the end, so the tracer re-runs continuously. `Render()` resizes the renderer + camera to the viewport, times the trace, and updates the FPS readout. `AppLayer::OnUpdate` drives the camera and calls `m_Renderer.ResetFrameIndex()` when it moves.

**Renderer (`Renderer.cpp`).** `Renderer::Render` branches on `Settings.UseGPU` (checkbox in the Settings panel, off by default) between the original CPU loop and `GpuPathTracer::Render`; `Renderer::OnResize` always resizes both paths so toggling mid-session is instant. `GetFinalImageDescriptorSet/Width/Height` likewise dispatch to whichever path is active — this is what `WalnutApp.cpp` draws via `ImGui::Image`.

CPU path: iterates pixels via `std::for_each(std::execution::par, ...)` over the cached `m_ImageHorizontalIter` / `m_ImageVerticalIter` iota vectors (rebuilt in `OnResize`). `#define MT 1` at the top of the file toggles the parallel path vs. a plain double loop. Per pixel:
- `PerPixel` (the "ray gen" stage) path-traces up to 5 bounces. Each bounce: `TraceRay` -> accumulate `material.GetEmission()` into `light`, multiply `contribution` by `material.Albedo`, then scatter with a cosine-ish `normalize(normal + randomInUnitSphere)`. The sky/`skyColor` term is computed but the `light +=` is commented out, so **scenes are lit only by emissive materials**. `Roughness`/`Metallic` are UI-editable but not yet used in shading.
- `TraceRay` does an analytic ray–sphere intersection loop over `m_ActiveScene->Spheres` and returns a `HitPayload` (distance, world position, world normal, object index); `ClosestHit` / `Miss` fill it. A miss is signalled by `HitDistance < 0`.

**GPU path (`GpuPathTracer.h/.cpp`, `shaders/PathTrace.comp`).** A hand-rolled Vulkan compute pipeline — a faithful GLSL port of the CPU math above (same PCG RNG, same 5-bounce loop, same disabled sky term) — built directly against the raw Vulkan handles Walnut's `Application` exposes (`GetDevice`/`GetCommandBuffer`/`FlushCommandBuffer`/`SubmitResourceFree`). It deliberately never touches `Walnut::Image` (which only supports CPU→GPU upload, not compute writes): it owns its own storage image (`m_DisplayImage`, kept permanently in `VK_IMAGE_LAYOUT_GENERAL`) and registers it directly with ImGui via `ImGui_ImplVulkan_AddTexture`, so there's zero CPU readback — the compute shader writes pixels the UI samples directly. A second storage image (`m_AccumulationImage`, rgba32f) mirrors the CPU's `m_AccumulationData`, reset whenever `FrameIndex == 1`. Scene data (capped at 64 spheres/materials) and camera matrices are pushed to the GPU every frame through persistently-mapped host-visible buffers (SSBOs/UBO); `Settings.SlowRandom` is CPU-only and gets disabled in the UI when GPU mode is active.

**RNG.** Two implementations selectable via `Settings.SlowRandom` (CPU path only): the default fast path is `Utils::PCG_Hash` / `RandomFloat` / `InUnitSphere` with a per-pixel seed (`x + y*width`, multiplied by `m_FrameIndex`, bumped by bounce index); the slow path calls `Walnut::Random`. The GPU path always uses the same PCG hash, ported to GLSL in `PathTrace.comp`.

**Accumulation.** `m_AccumulationData` (`glm::vec4` per pixel) sums `PerPixel` results across frames; the displayed color is `accumulation / m_FrameIndex`. `m_FrameIndex` increments each frame while `Settings.Accumulate` is on, and resets to 1 on camera movement, the Reset button, or toggling Accumulate off. `OnResize` early-returns if dimensions are unchanged, so it's cheap to call every frame.

**Camera (`Camera.cpp`).** Precomputes a world-space ray direction per pixel into `m_RayDirections` (via inverse projection + inverse view), recomputed on resize and on movement only. Controls: hold **right mouse** to look; **WASD** move, **Q/E** down/up; movement is frame-rate scaled by `ts`.

**Scene (`Scene.h`).** Plain structs: `Scene` holds parallel `std::vector`s of `Sphere` (position, radius, material index) and `Material`. The scene is hard-coded in the `AppLayer` constructor and mutated live through the ImGui "Scene" panel.
